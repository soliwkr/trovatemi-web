# TROVATEMI PROOF STORY v1 — Design System Lock

Status: **LOCKED for S01/S02 unless founder explicitly changes it.**

This is the visual/CRO contract for the Beauty campaign experience currently routed at `/beauty-check/`. The public experience does not need to call itself “Beauty Check”; Beauty remains the campaign/vertical layer, while Trovatemi remains the product.

## North star

> **TROVATEMI tone + Google decision environment + social-native Beauty + visual truth + direct response.**

The experience should feel like the moment a local customer searches, compares, trusts and chooses — then continue seamlessly into the owner’s own operating reality and the Trovatemi mechanism.

It must not feel like a SaaS dashboard, generic quiz, editorial microsite or agency landing page.

## Core journey

```text
campaign / DM / WhatsApp
→ hook
→ search the real business
→ show the real storefront
→ same-query context when defensible
→ “Peccato che Google non era lì” bridge
→ 5 private scenes
→ one dominant diagnosis
→ 3 concrete moves
→ show what manual execution looks like
→ show what Trovatemi turns into system
→ activation later when L3 is real
```

The persistent report in S02 should be the same visual story reopened, not a separate dashboard/PDF aesthetic.

## One-screen law

Every stage must contain:

1. **one dominant idea**;
2. **one visual truth**;
3. **one primary action**.

If a screen needs explanation to understand the main point, it is too weak.

## Visual language

### Master palette

- `Proof Black`: `#050505`
- `Proof Panel`: `#101010`
- `Signal Yellow`: `#F6BD00`
- `Signal Yellow Hot`: `#FFC400`
- `Proof White`: `#F7F7F2`
- `Muted Proof`: `#9D9D98`

Yellow is a **signal**, not decoration. Use it for the argument, number, diagnosis, CTA or annotation that must win the eye.

### Typography

Primary: **Archivo Variable** (or an approved condensed sans fallback already available in the project).

- Campaign headline: 900, uppercase, tight tracking, line-height ~0.84–0.92.
- Proof number: 900, oversized.
- UI/provenance: compact sans, not serif.
- Handwritten accent may appear only as a campaign/social annotation, never as body copy.

No editorial serif in the core Proof Story.

### Surfaces

Use three recurring surfaces only:

1. **Black campaign surface** — hook, diagnosis, emotional scenes.
2. **White decision surface** — Google/search/storefront truth and comparison.
3. **Yellow signal slab** — CTA, punchline, warning, diagnosis or “BAM” transition.

Avoid pill-heavy SaaS UI, pastel cards and ornamental gradients.

## Google decision environment

The product may borrow the *mental model* of local search:

- search field;
- business cards;
- rating / stars / review count;
- locality / category;
- photo blocks when the provider/legal/data contract supports them;
- map pin / local intent cues;
- multiple alternatives visible in one decision context.

Do **not** clone Google branding or imply ranking/endorsement. Do not invent maps placement, competitor rank, photos, hours or “Google prefers X”.

Preferred language:

> **Questo è quello che una cliente può vedere prima di scegliere.**

For comparative context:

> **Altri risultati reali emersi dalla stessa ricerca.**

Never call the same-query set a ranking or controlled cohort unless methodology actually supports that claim.

## Visual truth taxonomy

Every proof shown must belong to one of these classes:

### T1 — Provider truth
Verified public evidence from an approved provider at a known moment.

Examples: business name, category, locality/address, rating, visible review count.

### T2 — Same-query context
Other real results returned by the same explicit search context.

Can create tension, but cannot imply ranking causality or competitor quality.

### T3 — Owner truth
What the owner declared in the five private scenes.

### T4 — Deterministic Trovatemi conclusion
Diagnosis generated from versioned rules and explainable evidence.

### T5 — Product truth
Only capabilities Trovatemi/Climbo can actually deliver in the current product state.

If a visual cannot be classified T1–T5, do not show it as truth.

## Direct-response copy system

Public copy is short, visual and scene-led.

Preferred rhythm:

```text
TI CERCANO.
TI CONFRONTANO.
SCELGONO IN POCHI SECONDI.
```

```text
PECCATO CHE GOOGLE NON ERA LÌ.
```

```text
ECCO DOVE SI FERMA.
```

```text
FAI QUESTE 3 COSE.
IN QUEST’ORDINE.
```

Avoid internal vocabulary: maturity, pillars, reputation score, distribution platform, opportunity score.

## Campaign continuity

The experience should look like the ad/DM that sent the user there.

Campaign imagery can be cinematic, glamorous, TikTok/IG-native and highly art-directed. Once the user selects the business, the **real business evidence becomes the hero**.

Do not flood every product step with unrelated stock photography.

## Social-native Beauty grammar

The visual language may use familiar Beauty/social objects as practical proof:

- salon result photography;
- WhatsApp-style compliment moments;
- review card;
- reply card;
- IG Story / Reel / TikTok-style content mockups;
- WhatsApp Status-style output;
- QR / NFC table stand or tag;
- phone screen stacks;
- handwritten annotation / paint stroke.

These visuals must show the operational sequence, not merely decorate it.

## Proof Loop

The core product story is:

```text
CLIENTE FELICE
→ RACCOGLI
→ RECENSIONE
→ RISPONDI
→ RIUSA / CONDIVIDI DOVE OPERATIVO
→ PIÙ PROVA VISIBILE
```

The user should see what happens, not read a feature list.

### Move 1 — RACCOGLI
Visual object: customer moment + QR/NFC/request touchpoint.

### Move 2 — RISPONDI
Visual object: real-looking review/reply interaction.

### Move 3 — RIUSA / CONDIVIDI
Visual object: review becoming a social/proof asset only where the delivery capability is verified.

## Manual vs system reveal

After the three moves, show the cost of doing it manually:

```text
RICORDATI DI CHIEDERE
RICORDATI DI RISPONDERE
RICORDATI DI CONDIVIDERE
RICORDATI DI RIFARLO DOMANI
```

Then reveal Trovatemi:

> **MENO COSE DA RICORDARE. PIÙ PROVE CHE LAVORANO.**

or

> **TU PENSA ALLE CLIENTI. IL PASSAPAROLA CONTINUA A LAVORARE.**

Do not reveal the SaaS feature zoo.

## CTA system

One primary CTA per stage. Yellow slab/button, high contrast, verb-led.

Preferred examples:

- `GUARDA IL TUO CASO →`
- `CERCA LA TUA ATTIVITÀ →`
- `SÌ. FAMMI VEDERE →`
- `DAMMI LE 3 MOSSE →`
- `METTILO AL LAVORO →` (only when activation is real)

Secondary actions are quiet text links only.

Do not end the commercial journey with `Rifai il Check` as the main CTA. Restart can exist as a secondary utility only.

## Report rule

S02 report = **persistent Proof Story**, not dashboard.

Recommended chapters:

1. `ECCO COSA VEDONO`
2. `ECCO CON CHI TI CONFRONTANO` (same-query truth, if available)
3. `POI SUCCEDE QUESTO` — Peccato che Google non era lì
4. `ECCO DOVE SI FERMA`
5. `MOSSA 1`
6. `MOSSA 2`
7. `MOSSA 3`
8. `PUOI FARLO A MANO`
9. `OPPURE LO METTI A SISTEMA`
10. activation only when L3 is production-real

## Motion

Motion is allowed only to improve sequence comprehension:

- snap/reveal between proof chapters;
- number emphasis;
- slide-in comparison cards;
- loop arrows;
- phone/content stack transitions.

No decorative parallax, autoplay video or animation that delays the next action.

## Responsive rule

Mobile is primary.

- 9:16 creative mentality;
- giant single-idea headlines;
- tap targets ≥ 44px;
- no dense three-column layouts on mobile;
- proof cards become vertical swipe/stack where useful;
- CTA visible without hunting.

Desktop may widen the composition but must retain the same hierarchy.

## Cost discipline

Visual ambition must not create uncontrolled API cost.

- lookup starts on explicit submit, not typing;
- minimal fields on initial search;
- details only after selection;
- comparative context only at the chosen high-value transition;
- no repeated context fetch in the same session without reason;
- cache UI/session results where compliant and technically appropriate, while respecting provider terms;
- do not add Places fields because they look nice; each field needs a CRO/product reason and cost review.

## Prohibited

- fake ratings, review counts or competitors;
- invented maps ranking;
- fake social metrics (`8.7K`, `+2,500 saloni`, etc.) presented as Trovatemi proof;
- “Google prefers you/them” claims;
- customer-facing 0–100 score;
- decorative dashboards/bars;
- feature grids as the primary sales story;
- a second visual system for report/onboarding;
- Beauty becoming a separate product.

## Legal / trust backlog — NOT CURRENT S01 WORK

M0 must later add the production legal/trust shell: privacy, cookie policy/CMP, terms, consent provenance, footer/legal links, provider attribution/compliance and exact commercial/trial disclosure.

Do not interrupt S01 to build those pages now. Do not scale traffic before M0 passes.

## Design acceptance

A screen passes only if a founder can answer **yes** to all of these:

- Does it look like the same campaign the user clicked?
- Is the dominant idea understandable in ~2 seconds?
- Is the strongest visual claim true and attributable?
- Is the next action obvious?
- Does it feel closer to Google/local choice + social-native Beauty than to SaaS?
- Did we avoid adding API cost without a conversion reason?

If not, redesign the screen — do not patch it with more explanatory copy.
